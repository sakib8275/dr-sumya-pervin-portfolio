# UX-AUDIT-2026-08-04 — UI/UX, navigation & user-experience audit (round 4)

**Scope:** the patient-facing site (`public/`) — navigation, booking flow, modals,
mobile behaviour, accessibility, performance. **Not in scope:** the CMS admin
(operator-only, exercised locally), production CMS login (forbidden), the digest
worker (covered by its own thread).

**Method:** read of all of `public/index.html`, `public/js/main.js`,
`public/css/style.css`; live probing with puppeteer-core + system Chrome against
`wrangler pages dev` (desktop 1280px and mobile 375px); production header/state
probes with curl (doc-validity audit, same session). Screenshots of every
section on both viewports reviewed by the agent. The booking submit was
exercised with the Turnstile response stubbed page-side and the POST intercepted
(201) — the Turnstile/D1 wiring itself is already proven
(`handoffs/HANDOFF-2026-07-31-v3.md` evidence table, `tests/booking.test.mjs`);
what was under test here is DOM behaviour, which is identical either way.

**Context:** this audit ran on top of the F9 build. Two things the repo already
knew and this audit re-confirmed as *not* issues: anchors all resolve (0 broken
in-page links), no horizontal overflow at 375px, zero console errors in normal
browsing (Turnstile's own styled-`NaN` logs aside), Escape closes modals, a
focus trap exists, the pre-hydration submit guard works, and the server re-checks
everything the client hints at.

## Fixed in this session (all verified locally after the fix)

| # | Finding | Severity | Fix |
|---|---|---|---|
| F-UX-1 | **Booking success left the whole (reset) form visible** under the confirmation, and on mobile the confirmation itself could sit above the scroll position | High (operator-reported) | On success the modal now shows **only** the confirmation card (form + modal header hidden, `scrollIntoView`); the open handler restores form, header and clears status so a second booking works. Failure path deliberately unchanged (form stays populated) |
| F-UX-2 | **Every quiz-driven booking failed at the server.** `evaluateQuiz()` recommended `SERVICES_DATA` names (`PRP & Microneedling Therapy`, …) and "Book Recommended Procedure" assigned them straight into `#serviceType` — none were `<option>` values, so the select silently blanked (`selectedIndex -1`) and the API's required-field check rejected the POST with a 400 | **Critical** | Rec values now map to exact option values: acne→`Microneedling with Serums`, pigmentation→`Chemical Peels`, aging→`Facial & Neck Mesotherapy`, hair→`Hair Loss & Scalp Treatments` (**new option added** — it had no equivalent). All four branches verified to land on a valid `selectedIndex` |
| F-UX-3 | Submit result appeared with no focus move and no AT announcement | High (a11y) | `#bookingStatus` got `role="status" aria-live="polite"`; `#quizResultBox` got `aria-live="polite"`; all three modals got `role="dialog" aria-modal="true"` |
| F-UX-4 | The Process section heading was a verbatim duplicate of the `#results` heading ("Reveal ✦ Your Best Skin Yet" twice) | Low | New copy: "From First Consult ✦ to Lasting Results" |
| F-UX-5 | **All 18 content images loaded eagerly** — ~2.19 MB transfer on a warm desktop load, for an audience on mobile connections | Medium | `loading="lazy"` on the 17 below-fold images (hero stays eager as LCP). Warm transfer drops to ~0.70 MB |
| F-UX-6 | Tap targets below 40px at 375px: step dots **8×8**, testimonial nav 34, FAQ toggle 38, modal close 36 | Medium | Step dots: 24×24 hit area via transparent border + `background-clip` (visual dot unchanged; `box-sizing: border-box` makes the width the *outer* size — first attempt shrank the dot to nothing, caught on re-probe). Others bumped to 44px |
| F-UX-7 | **No-JS = blank page.** Every `[data-r]` element (nearly all content) started at `opacity: 0`, revealed only by IntersectionObserver — any JS failure left patients a white page | High (resilience) | Hidden state now gated behind `html.reveal`, added by main.js at the top of `DOMContentLoaded`. JS dead → content visible. Reduced-motion override strengthened to keep outranking the gate. ⚠️ The gate's first form (`html.reveal [data-r]`) outranked `[data-r].in` on specificity and hid *everything* — caught because screenshots came back blank; shipped form is `html.reveal [data-r]:not(.in)` |
| F-UX-8 | Services toggle shipped as "Show more" but renamed itself "Show more services" after one use | Trivial | JS now reuses the shipped label |

## Open recommendations (NOT fixed — need owner/product decisions or more care)

| # | Recommendation | Why it was deferred |
|---|---|---|
| R-1 | Add `width`/`height` (or `aspect-ratio`) to content images — all are dimensionless, a CLS risk | Per-image visual regression risk against the existing CSS; lazy-loading (the bigger win) shipped first |
| R-2 | The FAB stack (WhatsApp/book/top) overlaps right-edge content at 375px — quiz option buttons in the right column sit partly underneath | Needs a layout decision (content padding vs FAB repositioning), not a drive-by |
| R-3 | Remaining small tap targets: footer nav links 21px tall, gallery filter buttons 39px, the two CMS-trigger buttons 33px (operator-facing) | Cosmetic polish; the patient-critical controls were fixed |
| R-4 | Alt text is weak or misleading on reused stock: certs (`alt="FCPS"`), testimonials (`alt="Patient review"` ×3 identical), the before/after slider (the "Before" image is the hero portrait) | Tied to R-5 — fix together with real content |
| R-5 | **Content integrity:** testimonials and the before/after slider use stock imagery and unattributed quotes. Same class of issue as the "1500+ procedures annually" stat removed 2026-08-02 — an unsourced claim on a medical site | **Owner decision**: supply real consented photos/testimonials or remove the sections. Not an agent call |
| R-6 | Desktop nav omits `#quiz` and `#gallery`; the mobile drawer has both | Nav space is a design choice; flagged, not changed |
| R-7 | The gallery section shows "No photos found…" to patients whenever the CMS is empty — production has 0 photos **right now** | Hiding the section when empty is a product choice (the empty state also tells the doctor where to add photos) |
| R-8 | Closed-weekday rejection is server-side only: a patient can pick Thursday for DCIMCH and is told only after submit (the 400 does suggest the next open day) | Client-side weekday disabling per chamber duplicates `functions/lib/schedule.js` logic into the client — worth doing together with F10's booking specs |
| R-9 | `aria-pressed` on quiz option/filter buttons; `aria-expanded` + `aria-controls` on FAQ toggles; `.selected`/`.active` are visual-only states | Small, but each needs its own state-sync code; bundled here as one a11y polish item |
| R-10 | `autocomplete="new-password"` on `#cmsPinInput` / `#currentPinInput` / `#newPinInput` | Already a standing note (F8-SIGNOFF-F10-PROMPT "also open" #2) — still open |
| R-11 | Turnstile logs styled `NaN` console errors in automation (and possibly some real clients) | Third-party widget noise; cosmetic; nothing this repo controls |

## Verified-good (no action)

- 0 broken in-page anchors; `#book` falls back to the footer CTA without JS
- No horizontal overflow at 375px; drawer opens/closes; scrollspy works
- Zero site console errors; the only failed requests in automation are Turnstile's own telemetry
- Escape closes modals; focus trap cycles inside the open modal; `:focus-visible` styles exist
- Pre-hydration submit guard (`formguard.js`) + disabled-until-hydrated submit button
- Server re-validates phone/date/schedule (`validateSlot`), so client hints can be liberal
- WhatsApp FAB and nav number stay hidden until a real number is configured (L6 made it live)
- Branded noindex `404.html`
- `prefers-reduced-motion` disables transitions (and after this session, defeats the reveal gate outright)

### Finding 1 — P2: the preview reveal replays on CMS tab switches

**Reviewer:** the new comment claims re-picking swaps the src "without
re-animating" (true), but omits that `cms.js` display-flips `.cms-tab-content`
on every tab click, and showing a `display:none` subtree restarts descendant
CSS animations in Blink/WebKit — so returning to the Uploads tab replays the
reveal while a preview is showing. (The modal open/close does NOT replay it —
`.modal-overlay` uses `visibility`, not `display`.)

**Disposition: accepted — comment fixed, behavior kept.** The tab-reshow
replay is visually benign (the whole tab panel is re-appearing; the preview
fades in with it) and gating it away would need a JS class hook, outside this
PR's no-JS boundary. The comment now states both caveats truthfully.

### Finding 2 — P2: the kill-switch leaves the visibility delay, so a closing dialog stays in the tab order 200ms under reduced motion

**Reviewer:** the admin reduce block sets `transition-duration: .01ms
!important` but never `transition-delay`, so the base overlay's
`visibility 0s linear 200ms` survives — under reduce the dialog snaps
invisible yet remains focusable for 200ms, exactly the residual the stepping
mechanism exists to close (pre-existing at 300ms; this PR edited the line).

**Disposition: accepted — fixed.** `transition-delay: 0s !important` added to
the kill-switch's `*` rule. Verified safe in this sheet: a grep shows the
only non-zero transition delay in style.css is the one being killed (the
`.active` visibility is already `0s`); site.css's discrete stepping delays
are a different sheet, untouched.

### Finding 3 — P3: `160ms` literals next to `var(--t-press)` in `.btn-danger`

**Disposition: accepted — tokenized.** The two color durations now use
`var(--t-press)` (same value, no hand-typed duplicate of a token in the same
declaration). `.modal-close`'s `.3s` colors stay literal — matching `.btn`'s
existing register; `240ms` on the armed state stays literal (deliberately
slower, no token exists).

### Finding 4 — P3: `preview-in` at 6px "mirrors rise-in" — which is 8px

**Disposition: accepted — aligned to 8px.** The plan's own text claimed to
mirror `rise-in` while specifying 6px; the keyframe now genuinely mirrors
(`translate: 0 8px`), same as `site.css`'s `rise-in`.

### Finding 5 — P3: `.modal-close:active` lacks the `:not(:disabled)` guard

**Disposition: accepted — guard added** (`.modal-close:not(:disabled):active`),
matching `.btn`'s form. The ✕ is never disabled today; consistency only.

### Finding 6 — P3: an armed delete button can auto-disarm while the modal is hidden (pre-existing JS)

**Reviewer:** `confirmOnButton` never clears the 6s timer on modal close, so
reopening inside the window can animate a disarm the admin didn't witness.
Pre-existing; the PR's new transitions are what make it noticeable.

**Disposition: acknowledged — JS lane, not this diff.** Noted for a future
admin JS pass; no plan file yet (single small guard in `confirmOnButton`).

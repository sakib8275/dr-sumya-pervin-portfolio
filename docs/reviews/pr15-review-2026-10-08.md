### Finding 1 — P1: fallback-close race (site.js)

**Reviewer:** the `closing` guard closes instantly on a second mid-fade Esc but
leaves the 200ms timer armed; reopening a sheet inside the window lets the
orphan timer close the fresh dialog (and `is-out` lingers until it fires).

**Disposition: accepted — real race, fixed.** `shut()` now routes a second
dismissal through `finishFallbackClose()`, which clears the timer, strips
`is-out`, resets the flag and closes at once; the timer itself calls the same
function, so no path leaves state armed. Verified in-browser (VT stubbed off,
/prices/): open → Esc → Esc at ~40ms (closed, no `is-out`) → reopen at ~80ms
(`pkg-in` playing, no residue) → still open with focus inside at +400ms, past
the old orphan-timer deadline.

### Finding 2 — P2: reduce-motion specificity for the Learn cards (site.css)

**Reviewer:** `.h-learn .h-learn-card` (0,2,0) and its gated `:hover` (0,3,0)
outrank the reduce block's `.h-learn-card` (0,1,0) / `.h-learn-card:hover`
(0,2,0), so the lift survives `prefers-reduced-motion: reduce`.

**Disposition: accepted — but pre-existing, not introduced by this PR** (the
gap existed on master; the review surfaced it because the PR touches exactly
this area). Fixed on the branch: both reduce selectors now carry the compound
`.h-learn .h-learn-card` form, matching base specificity with the reduce block
later in the file.

### Finding 3 — P3: retarget wording overclaims (site.css, site.js, STATUS.md)

**Reviewer:** "a rapid step eases back from wherever the digit is" is wrong —
`.is-swap` carries `transition: none`, so the forced-reflow sequence snaps
instantly to the from-state and then settles; there is no mid-flight retarget.

**Disposition: accepted.** The behavior is correct (instant set + settle is
what the flip pattern requires; the 8px dip reads as a swap, not a pop) but the
words were not. Comments in site.css/site.js, STATUS.md and the PR body now
say "resets instantly to the from-state and settles in 240ms".

### Finding 4 — P3: `overflow: hidden` on accordion content (site.css)

**Reviewer:** suggests `overflow: clip` so open items don't establish scroll
containers (citing focus-ring clipping).

**Disposition: accepted.** The rationale is imprecise — `clip` clips paint
too — but avoiding a scroll container is right and matches the canonical
`::details-content` pattern; swapped to `overflow: clip` (safe: the selector
itself already requires newer engines than `clip` support).

### Finding 5 — P3: `::backdrop` doesn't fade on the fallback exit (site.css)

**Reviewer:** the backdrop paints its own box and inherits nothing from the
dialog, so it blinks out only when `close()` lands, 200ms after the sheet has
faded.

**Disposition: accepted — verified live (`::backdrop` computed animation-name
`pkg-backdrop-out` under `.is-out`).** Added
`.pkg-view.is-out::backdrop { animation: pkg-backdrop-out 200ms var(--ease) both }`.

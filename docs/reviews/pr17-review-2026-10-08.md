### Finding 1 — P2: focus never lands on three of the four tool outputs (site.js show())

**Reviewer:** only `#scOut` carries `tabindex="-1"`; `#skinOut`, `#moleOut`,
`#prepOut` are plain `hidden` divs, so `out.focus()` silently fails there —
pre-patch nothing scrolled or focused, post-patch `scrollIntoView` scrolls
the panel without moving focus, jumping the page under a keyboard user whose
focus stays on the submit button.

**Disposition: accepted — fixed.** `tabindex="-1"` added to the three outputs
in `content/pages/tools.mjs` (the generator; pages rebuilt), matching `#scOut`
exactly. Verified in-browser (mobile 390×844, mole tool): `activeElement.id
=== "moleOut"` after submit.

### Finding 2 — P2: no scroll-margin against the two sticky bars (site.css)

**Reviewer:** site.css declares zero `scroll-margin`; `.s-nav` (sticky top,
78px / 64px ≤962px) and `.m-sticky` (sticky bottom, ~49px + safe area) can
cover the glided result — the heading under the nav on tall panels, the
mole-check priority CTA behind the mobile bar. Notes `say()`/`confirmBox()`
share the gap (pre-existing pattern).

**Disposition: accepted — fixed for `.tool-out`.** `.tool-out` now declares
`scroll-margin-block: 88px calc(60px + env(safe-area-inset-bottom))`.
Verified in-browser: mole result bottom-aligns at viewport 784 with the bar
top at 788 (the 60px end margin honored); the tall skin-check result's
heading lands at 161px, clear of the 64px nav. The `say()`/`confirmBox()`
sites stay as they are — separate surface, not this PR's boundary.

### Finding 3 — P3: reduced motion kills .pkg-close's new colour fade

**Reviewer:** the diff adds `.pkg-close` to the blanket `transition: none`
list, but a colour-only fade is a state change, not movement — the block's
own comment says "drop the movement, keep the state change", and `.btn`
keeps its colour fades there.

**Disposition: accepted — fixed.** `.pkg-close` moved out of the kill list
into a dedicated rule inside the reduce block:
`.pkg-close { transition: background-color var(--t-press) var(--ease-out); }`
— the hover fade persists, the scale press stays dead via the `scale: none`
list.

### Finding 4 — P3: dead shared-rule entry for .pkg-close

**Reviewer:** the shared press rule's `transition: scale` for `.pkg-close`
is wholly overridden by the later `.pkg-close` rule's own transition
shorthand, so the shared entry is dead weight that looks like coverage.

**Disposition: accepted — fixed.** `.pkg-close` dropped from the shared
transition list (its own rule owns the transition — the documented
`.reel-arrow` / `a.chip` pattern); the shared `:active { scale: .98 }` keeps
it. Comment updated to say the sheet close carries its own.

### Finding 5 — P3: drawer ✕'s press release is never seen (pre-existing)

**Reviewer:** `.drawer` transitions only `transform`, not `visibility`, so
`shut()` hides the panel in the same frame — the ✕ sinks on press but the
panel blinks out instead of sliding, so the ease-back never renders. Explicitly
flagged as pre-existing, "worth its own lane, not a blocker".

**Disposition: acknowledged — not this PR.** Recorded as plan 011
(`plans/011-drawer-exit-visibility.md`, TODO).

## P1 — `.card` hover lift never animates — REAL, FIXED (commit 2nd on branch)

qwen: the new `.card` transition lists `border-color`, `box-shadow`, `scale` —
but not `translate`, while the lift moved to `translate: 0 -2px`. The lift
therefore snaps in and out. It also noted the irony that this reviewer's own
probe line — "`translate` holds `-2px` in every frame" — was the evidence: a
transitioned lift would NOT hold -2px in the first frames. Root cause is in
the plan's target CSS for `.card` (the `translate` leg is present in the
plan's `.h-learn-card` target but missing from its `.card` target).

**Empirical confirmation** (frame probe, Playwright Chromium): before the fix,
`translate` went `none → 0px -2px` in one frame at ~43ms. **Fix**: added
`translate var(--t-press) var(--ease-out)` to `.card`'s transition (matching
the plan's own `.h-learn-card` target). After: `0 → −1.02 → −1.53 → −1.78 →
… → −2px` over ~160ms, ease-out settle. Press compose re-verified (scale
1→.99 while translate holds −2px); reduced motion still kills both.

Process note: the original probe sampled the hover state only after a 250ms
settle, so the snap was invisible in its output; the compose assertion passed
and the lift assertion was never actually asserted.

## P3s — accepted as notes

1. **Comment inaccuracy (fixed)**: "translate so it composes with the press's
   scale" states a false invariant — per CSS Transforms 2, `transform` and
   `scale` already compose (multiplicatively). The real difference is that a
   `transform` lift would be shrunk 1% by the press (−2px → −1.98px) while a
   `translate` lift holds exact. Both this PR's comment and the pre-existing
   tier-card comment (`:703-704`) rewritten to state the true behaviour.
2. **`--t-press` used for a hover lift**: plan-specified (the plan's
   `.h-learn-card` target introduced it); a future press-tier retune will
   also retune the lifts. Accepted.
3. **Curve deltas undercounted as "identical 200ms"**: true — `ease` →
   `var(--ease)` on learn-card border-colour and `.card` box-shadow is an
   intended curve unification, not value-identical. PR body wording stands
   corrected here.
4. **JS comment coupling**: `site.js` "The exit slides for 300ms" now describes
   `var(--t-sheet)` in CSS; a `--t-sheet` retune would stale the comment (same
   pattern as the pkg-out 200ms pair). Deferred backlog note; PR stays
   CSS-only.

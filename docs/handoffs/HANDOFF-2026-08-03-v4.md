The plan said 3 generated + 8 static `onclick`. Re-counted by hand: **12 inline
handler attributes, not 11.**

| Where | What | Replaced with |
|---|---|---|
| `index.html:457-463` | 7 × `onclick` closing the mobile drawer | one delegated listener on `.mobile-drawer-links` |
| `index.html:602` | `onclick="cmsLogout()"` | `id="cmsLogoutBtn"` + `addEventListener` |

| `main.js:1143` | generated `onclick="deleteCMSItem('${item.id}')"` | `data-cms-action="gallery-delete"` |
| `main.js:1196-1197` | generated status/delete `onclick` | `data-cms-action="appointment-status"` / `"appointment-delete"` |

Two of these were more than a refactor:

**The Logout button had never worked.** `cmsLogout` is declared *inside* main.js's
`DOMContentLoaded` callback, so it was never a global and `onclick="cmsLogout()"`
threw `ReferenceError` on every click. Nobody noticed because an inline handler
that throws looks exactly like a button that does nothing. Removing the attribute
fixed it as a side effect.

**The `onsubmit` was load-bearing.** The booking form has no `action`/`method`, so
a submit before main.js hydrates did a native GET to `/?`: page reload, fields
cleared, patient's booking lost with no message. That is the regression the
attribute was added to fix, and the CSP would have silently undone it. It now
lives in `public/js/formguard.js`, loaded **blocking from `<head>`** so it is in
place before the form is parsed — a capturing `submit` listener on `document`,
which sees the event because `submit` bubbles. `preventDefault()` does not stop
propagation, so main.js's own handlers still run; verified by completing a real
booking, a photo upload and a settings save.

The generated buttons also interpolated `${item.id}` **unescaped** into an
attribute. That is gone with the attribute.

## 2. What shipped in the header

`functions/_middleware.js`, on every response (it is the root middleware, so it
runs for static assets too):

```
script-src 'self' 'nonce-<per-request>' https://challenges.cloudflare.com https://static.cloudflareinsights.com;
frame-src https://challenges.cloudflare.com;
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
img-src 'self' https: data:;
object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

plus `Permissions-Policy` (accelerometer, camera, geolocation, gyroscope,
magnetometer, microphone, payment, usb all `()`), `X-Frame-Options: DENY`,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
and `Strict-Transport-Security: max-age=31536000; includeSubDomains`.

**Judgement calls, so the next agent does not have to re-derive them:**

- **`default-src`, `connect-src` and `font-src` are deliberately unset.** Turnstile
  issues its own requests, including to `*.challenges.cloudflare.com` subdomains
  that Cloudflare documents as normal-and-failing, and a `connect-src` that misses
  one breaks every booking with a 403 that looks identical to a working system.
  `script-src 'self'` is what actually stops XSS here; the rest is blast radius.
- **HSTS was sent only after L5 was re-verified live** (`http://` → 301 `https://`,
  `www` → 301 apex), not just read from STATUS.
- **`includeSubDomains` is justified, not assumed.** The zone's DNS has exactly two
  HTTP hostnames, apex and www, both Cloudflare-proxied and both already HTTPS-only.
  Re-check that before adding a subdomain. **No `preload`** — that one is genuinely
  one-way and belongs to the owner.
- `'unsafe-inline'` stays in `style-src`: ~55 inline `style` attributes and a
  `<style>` block in `404.html`. Cosmetic surface, not a script one.

## 3. ⚠️ The thing local testing cannot catch — read this before any future header change

The first deploy (`b43265e4`) was correct for everything in this repository, passed
every test then in the suite, and produced **zero CSP violations locally**. On the
apex it broke two
scripts, because **the zone injects scripts into the apex HTML that are not in this
repo**:

1. **Cloudflare JavaScript Detections** — an *inline* script whose body contains
   `window.__CF$cv$params={r:'<ray id>',t:'<timestamp>'}`. Because the ray id
   changes on every request, **a CSP hash can never match it**. It is auto-enabled
   by Bot Fight Mode and, on this plan, cannot be turned off.
2. **The Web Analytics beacon** from `static.cloudflareinsights.com`. Blocking it
   silently kills the owner's analytics.

**Neither appears on `*.pages.dev`** — the apex is HTML-rewritten by the zone, the
preview host is not. This is the same "apex page ≠ pages.dev page" gotcha already in
the carry-forward list, with teeth.

The fix is Cloudflare's documented one: **emit a per-request nonce in the CSP.**
Their CDN parses the CSP *response header* and stamps that nonce onto the script it
injects. Verified live — the `nonce-` in the header and the `nonce=` on the injected
`<script>` are the same value on the same request. Nothing in this repo needs the
nonce; every script we ship is external and matches `'self'`. Adding a nonce does
**not** disable the host sources (only `'strict-dynamic'` would), so Turnstile is
unaffected.

Deploy `74c3bd4b` carries the fix. **After any future header change, re-check the
console on `https://drsumyapervin.com/` itself, not only locally.**

## 8. Carry-forward gotchas

Everything in `-v3` §9 still holds. Added by this session:

- **The apex HTML is not the HTML you deployed.** The zone injects scripts into it
  that never appear on `pages.dev`. Verify header changes on the apex.
- **A wrong CSP and a wrong Turnstile hostname produce the identical symptom** —
  every booking 403s, nothing in the console. If it starts right after a header
  change, roll back to `f64b9221` (last pre-F9) rather than to `5423d45e`.
- **`wrangler pages dev` starts with an unmigrated local D1.** `/api/gallery` and
  `/api/config/public` 500 until you run the migration with `--local`. Looks like a
  broken API; is not one.
- Playwright's saved console logs are written as binary, so plain `grep` skips them
  silently and reports zero matches. Use `grep -a`.

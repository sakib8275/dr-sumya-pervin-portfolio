## Traps found and disarmed this session

1. **Alias propagation is per-asset.** Fresh-deploy 404s on brand-new files
   (favicon.svg, sitemap.xml) cleared themselves in ~20 s. Verify on the
   `<deployment-id>.…pages.dev` URL first to distinguish "not deployed" from "alias lag".
2. **F4 broke old fixtures twice over** — invented chamber names (`'Alliance'`) and fixed
   calendar dates (go stale the day after). All fixtures now derive from `schedule.js`:
   `nextOpenDate(CHAMBER, addDays(dhakaParts().dateStr, 1))`. If you add a booking test,
   use that and a unique phone (the 409 guard fires across tests otherwise).
3. **The orphan test's first assertion was wrong**, not the fix: earlier tests
   legitimately leave objects in the per-file bucket, so the invariant is "the failed
   insert added nothing", not "the bucket is empty".
4. **`main.js` carries literal `\uXXXX` escapes in template literals** — match them
   byte-for-byte when editing the booking status renderer.
5. **Edit anchors on `read` output render `\u2014`-style escapes literally.** If an edit
   fails to match, re-read the exact lines instead of retyping.

  `.test-build/`; `scripts/build-test-worker.mjs` blanks `CLOUDFLARE_API_TOKEN` for itself.
- **Remote D1 writes and `pages secret put` are operator-run** (classifier-blocked for
  agents). Reads work. `wrangler pages deploy` **ran fine from the agent** this session.
- **Local D1 starts empty** — apply `migrations/001_schema.sql --local` + seed a
  throwaway PIN before any local browser test. Never the production PIN.
- **`<select>` labels differ from values** (`chamberSelect`, `serviceType`) — automate by
  label, assert by value. The server now rejects anything but the exact values.
- **Never serve statically** — `/api/*` 404s and the site looks broken in ways that
  aren't real. Use `npm run dev`.
- **Secret presence check:** `[ -n "$VAR" ] && echo SET || echo UNSET`. Never
  `${VAR:-no}` — that prints the value, which is how the token leaked on 2026-07-30.
- **Scope discipline:** `~/Desktop/portfolio-astro/` and `~/Desktop/Portfolio/` are
  different projects. Do not read, edit, or report on them.

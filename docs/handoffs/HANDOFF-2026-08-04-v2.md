## 3. The critical find: quiz-driven bookings all failed

`evaluateQuiz()` recommended `SERVICES_DATA` names ("PRP & Microneedling
Therapy", "Chemical Peels & Resurfacing", "Hair Loss & Scalp Treatments",
"Facial Rejuvenation & Hydration") and `bookQuizRecBtn` assigned the string
straight into `#serviceType`. **None of them are `<option>` values** — the
select silently blanked (`selectedIndex = -1`), the submit sent `service: ''`,
and the API's required-field check rejected it with a 400. The patient got the
failure card after a real Turnstile solve, on a path the site itself
recommended. Live-probed before the fix: `serviceType.value === ""`.

Fixed by mapping to the select's own vocabulary (acne→`Microneedling with
Serums`, pigmentation→`Chemical Peels`, aging→`Facial & Neck Mesotherapy`) and
**adding the missing `Hair Loss & Scalp Treatments` option** — it had no
equivalent at all, and the practice does treat hair. The server accepts any
non-empty string ≤120 chars for `service`, so the new option needs no API
change. All four branches verified to land on a valid `selectedIndex`.

**Lesson for the repo:** three service vocabularies coexist — the select's 8
options (booking), the svc cards' `h4`s (which match the select), and
`SERVICES_DATA`'s 8 richer names (service modal + formerly the quiz). The svc
cards → modal → booking path worked *because* cards match the select. Anything
new that sets `#serviceType.value` must use option values; if F10 adds specs,
pin all four quiz branches.

## 4. Rest of the UX batch (all local, all verified)

Full details + method: `docs/audits/UX-AUDIT-2026-08-04.md`. Short list:

- **a11y:** `role="status" aria-live="polite"` on `#bookingStatus`,
  `aria-live` on `#quizResultBox`, `role="dialog" aria-modal="true"` on all
  three modals.
- **Perf:** `loading="lazy"` on 17 below-fold images (hero stays eager).
  Warm-transfer probe: **2.19 MB → 0.70 MB**.
- **Tap targets:** step dots 8px → 24px hit area (transparent border +
  `background-clip`; **`box-sizing: border-box` makes `width` the outer size** —
  the first attempt set `width: 8px` + 16px border and the dots vanished),
  `.faq-send` / `.modal-close` / `.tst-nav` → 44px.
- **No-JS blank page:** `[data-r]` hidden-start is now gated behind
  `html.reveal`, added at the top of main.js's `DOMContentLoaded` (before the
  awaits, so no visible-then-hidden flicker on slow connections). JS dead →
  content visible. ⚠️ **The gate needs `:not(.in)`** — without it, it outranks
  `[data-r].in` on specificity and *everything* stays hidden. That broken first
  form is exactly what the blank screenshots caught. The reduced-motion
  override was strengthened to keep outranking the gate.
- **Copy:** the Process section's heading was a verbatim duplicate of
  `#results`' ("Reveal ✦ Your Best Skin Yet" ×2) → now "From First Consult ✦
  to Lasting Results"; the services toggle renamed itself on first use → now
  keeps the shipped "Show more" label.

Open recommendations (11, with deferral reasons) are in the audit doc. The ones
needing **owner decisions**: R-5 (stock testimonials / before-after imagery —
same class as the removed unsourced stat), R-7 (gallery shows an empty state to
patients; production has 0 photos). R-10 (`autocomplete="new-password"` on the
PIN fields) was already standing.

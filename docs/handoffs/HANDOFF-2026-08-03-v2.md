## What changed beyond the bug list (and why)

- **The crons are no longer hand-written.** `cronForChamber()` derives each cron
  from `CHAMBERS` + `CUTOFF_MIN` in `schedule.js` (cutoff → UTC → cron day list),
  and a test asserts `workers/digest/wrangler.toml` matches that derivation. The
  failure this prevents is silent and expensive: change a chamber's hours, and the
  booking cutoff moves while the digest keeps firing at the old time, mailing a
  list that is not final. `cronForChamber` also throws if a cutoff would cross UTC
  midnight, because the day-of-week list would then need shifting.
- **Logic and runtime are split.** `digest.js` is pure and imports nothing from
  workerd, so it is testable in plain Node; `index.js` is only `scheduled()` plus
  the email transport. `cloudflare:email` cannot be imported outside workerd, which
  is why the split exists at all.
- **The transport tries both binding generations.** Cloudflare has an older
  Email-Routing `send_email` binding that takes `new EmailMessage(from, to, rawMIME)`
  and a newer Email-Service one that takes `{from, to, subject, text}`. Which is
  live depends on how the human onboards the domain. `index.js` tries raw MIME
  first (what Task 13 sets up), falls back to the object form, logs which worked,
  and rethrows the original error if both fail. **This is the one part no test can
  settle — it needs a real send.**
- **The body is base64.** Patient names and notes are free text and may be Bengali;
  an unencoded multi-byte body is not valid 7-bit SMTP content. Headers include a
  hand-built RFC 5322 `Date` (`toUTCString()` emits "GMT", which strict MTAs reject)
  and a `Message-ID`.

## Why it was not deployed

The prompt's "done" list says deploy even if the email prereqs are missing. I did
not, and this is the judgment call to overturn if you disagree:

- With Email Routing `unconfigured` and `DIGEST_TO` blank, a deployed worker does
  nothing twice a day except log `not configured`.
- `DIGEST_TO` is a `[vars]` value, so setting it **requires a redeploy anyway**.
  Deploying now buys no verification and leaves a cron writing error logs.
- Nothing about the deploy is hard: `cd workers/digest && npx wrangler deploy`,
  one command, after Task 13.

## Traps worth keeping

- **`send_email` in wrangler.toml is `[[send_email]]`**, not
  `send_email = [{ type = "send_email", … }]`. The scaffold's form is not valid
  config; `--dry-run` is how you find that out in five seconds instead of at deploy.
- **A verified destination is not optional.** Cloudflare refuses delivery to an
  unverified address, so "deploy and see" cannot substitute for Task 13.
- **`wrangler deploy` must run from `workers/digest/`**, never the repo root — the
  root `wrangler.toml` is the Pages project.
- **`--dry-run` proves the bundle and the bindings without touching the account.**
  It resolved the `../../functions/lib/schedule.js` import, which was the one thing
  about the cross-directory reuse that could have failed at deploy time.

### Why Miniflare rather than `wrangler pages dev`

`verifyTurnstile` requires siteverify to return **both** the expected `action` and a hostname in
`TURNSTILE_HOSTNAMES`. Cloudflare's always-pass testing keys mint a dummy token carrying **no
action**, so they can never satisfy that check — and a browser-solved token is not repeatable
(v3 recorded the widget failing to re-arm within 20s after `turnstile.reset()`).

So the positive booking path can only be made deterministic by intercepting siteverify
**server-side**. Miniflare's `outboundService` does that; `wrangler pages dev` has no equivalent.
Everything else stays real: `tests/helpers/harness.mjs` runs the **actual worker compiled by
`wrangler pages functions build`**, so the real routing table and `_middleware.js` are under test,
with real D1 and real R2.

**Do not replace this with hand-rolled handler imports.** The two defects below were only visible
because the compiled route table was in play.

### The anonymous requirement, enforced structurally

G09 survived a full audit because every check was run while logged in. That is now impossible to
repeat by accident:

- `harness.anon()` **throws** if a test passes an `Authorization` header. Authenticating requires
  the explicit `asAdmin()` wrapper, so it is always visible in the test body.
- `tests/anonymous.test.mjs` walks every route with no credentials and pins each status **and**

### The siteverify stub

Tests pass a magic token as `cf-turnstile-response`; the stub in `harness.mjs` turns it into the
response Cloudflare would really send. `tokens.good('booking')`, `tokens.fromHostname(...)`,
`tokens.singleUse(...)`, `tokens.rejected()`, `tokens.siteverify500()`, `tokens.networkError()`.
Any outbound request that is **not** siteverify is recorded in `siteverify.unexpectedOutbound` and
fails — the suite can never quietly reach the internet.

### Harness gotcha, already solved — do not rediscover it

Miniflare's `dispatchFetch` **stringifies a `FormData` body to `"[object FormData]"` and sends it
as `text/plain`.** Every multipart test then 400s with *"Invalid request body"*, which reads as a
broken upload endpoint. `buildRequest()` pre-encodes FormData through a Node `Request` and carries
undici's boundary across. Same reason `dispatchFetch` is given `(url, init)` rather than a
`Request` — passing one throws *"Failed to parse URL"*.

## Two live defects found and fixed

Both were client/server route mismatches. Both were invisible to every prior audit because no test
had ever issued the request the CMS actually issues.

### 1. The CMS "Update Status" button 404'd

`main.js` called `PUT /api/appointments/{id}/status`. Pages routes
`functions/api/appointments/[id].js` to `/api/appointments/:id` — **`[id]` matches exactly one
segment** — so the two-segment path fell through to the static-asset handler and returned the 404
HTML page. `api()` turned that into *"Server returned 404 and no JSON"* and the CMS showed
*"Failed to update status"*. **The doctor could not change an appointment's status at all.**

Fixed by dropping the `/status` suffix.

### 2. Publishing a photo failed outright

`main.js` posted the file to `POST /api/gallery/upload`, which does not exist. The `catch`
substituted `imagePath = 'assets/clinic.jpg'` — and that value is **not an accepted
`image_path`** either (`safeImageUrl` allows only `/api/uploads/…` or absolute http(s)), so the
follow-up `POST /api/gallery` returned 400 and the admin got *"Failed to save"*.

Worth being precise: this was **not** "uploads silently show the stock image". Photo publishing
was broken end to end, with and without a file.

Fixed by sending **one multipart `POST /api/gallery`** carrying `title`, `category`, `caption` and
`image` — the branch `functions/api/gallery/index.js` already implements, R2 `put` included. The
form's **`photoUrlInput` field was never read by any code**; it is now wired to the endpoint's
`image_url` parameter. With neither a file nor a URL the form says so instead of publishing a
broken row.

`tests/contract.test.mjs` was confirmed to **fail on the reverted `main.js` and pass after** — it
is a real regression gate, not a tautology.

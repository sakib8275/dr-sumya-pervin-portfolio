# Handoff — Dr. Sumya Pervin Portfolio

## Project Overview

Single-page static portfolio for Dr. Sumya Pervin, MD — a dermatologist and aesthetic medicine specialist based in Dhaka, Bangladesh. Built with vanilla HTML5, CSS3, and ES6+ JavaScript (no frameworks, no build tools, no backend). Targets patients on mid-range Android phones (360–390px viewport) who want to book consultations.

## Known Issues / Gotchas

- **localStorage-only persistence:** All booking data, gallery images (base64), and CMS settings vanish if the user clears cache. The JSON backup/export feature exists for this reason.
- **Booking flow misdirection:** The user sees "Appointment Details Saved — Send to Doctor" and must manually click WhatsApp/Telegram. No data reaches the clinic without that second action. This is by design (no server) but easy to miss.
- **Hero gradient contrast is inherently fragile:** The gradient varies spatially. The text-shadow + overlay fix works across the full gradient range but any change to the hero gradient colors needs contrast re-verification.
- **CMS pin security:** PIN `1234` is the default and stored in `localStorage`. Previous audit already removed the hint from the UI ("Default PIN: 1234" is gone from the CMS login description — that was fixed in commit `9158c1e`). But the default is still `1234` in code (`js/main.js` line 38).
- **netlify deployment:** No continuous deployment configured. Deploy via Netlify web UI drag-and-drop of the repo folder, or set up CI from the GitHub repo.

## Suggested Future Work (Out of Scope, Not Started)

- **Structured data (JSON-LD):** Add `MedicalBusiness` and `Physician` schema for Google SEO — no schema markup exists.
- **Open Graph / social preview:** `index.html` has no `og:title`, `og:description`, `og:image` meta tags — rich link previews fail on WhatsApp/ Facebook.
- **Service worker / offline:** A `service-worker.js` would make the site work offline for returning patients on slow connections.
- **Booking confirmation page:** Instead of a modal flash, a dedicated confirmation page or persistent banner would give users more confidence.
- **Bengali language toggle:** The site is English-only. A toggle would serve the primary patient demographic.
- **Analytics:** No tracking. A privacy-preserving option (Plausible, Fathom) could give the doctor visibility into which services get the most interest.

> **Read the Security History section before deploying anything.** A prior version of

> error had consequences — see below.

## Project Overview

Single-page portfolio for Dr. Sumya Pervin, MD — a dermatologist and aesthetic medicine specialist based in Dhaka, Bangladesh. Built with vanilla HTML5, CSS3, and ES6+ JavaScript (no frameworks, no build tools). Backend is Cloudflare Pages Functions + D1 (SQLite) + R2 (images). Targets patients on mid-range Android phones (360–390px viewport) who want to book consultations.

---

## Architecture

### Hosting: Cloudflare Pages — and only Cloudflare Pages
- Static assets are served from `public/` **only**. Everything else in the repo (docs, migrations, `wrangler.toml`, `functions/` source) stays unpublished.
- API lives in `functions/` (Pages Functions)
- Custom domain: `drsumyapervin.com` (Cloudflare-managed)
- **Netlify is not a supported target.** It cannot execute Pages Functions, so every `/api/*` route fails there and booking, gallery, and the CMS all break. `netlify.toml` exists solely to make an accidental redeploy fail safely.

### Database: Cloudflare D1 (serverless SQLite)
- 4 tables: `admin_settings`, `appointments`, `gallery`, `contact_messages`
- Migration file: `migrations/001_schema.sql`
- Run via: `wrangler d1 execute dr-sumya-pervin-db --remote --file=migrations/001_schema.sql`

### Image Storage: Cloudflare R2
- Bucket: `dr-sumya-gallery`
- Gallery images uploaded via CMS and served at `/api/uploads/:filename`
- Uploads are restricted to JPEG/PNG/WebP at 2 MB, and served with `nosniff`

### Auth: JWT (stateless)
- Library: `jose` (HS256)
- Admin PIN is PBKDF2-SHA256, 100k iterations, per-install salt in `admin_settings.pin_salt`
- **The PIN plaintext is deliberately not recorded in this repository.** It is held by the practice. If it is lost, reseed `admin_settings` with a new hash and salt.
- Token stored in `localStorage` as `cms_token`, 24h expiry
- `JWT_SECRET` has no fallback. If it is unset, login fails with a 500 — by design.

### Frontend
- `public/index.html` — single-page app
- `public/css/style.css` — CSS custom properties design system, glassmorphism, full-width layout
- `public/js/main.js` — `api()` helper with auto JWT header, CMS panel, gallery render, booking form, quiz, slider, accordion, carousel
- `public/404.html` — real 404, so unknown paths don't silently return the homepage

## Security History

### 2026-07-28 — Public credential exposure (contained)

**What happened.** The repo was deployed to `drsumyapervin.netlify.app` with the publish directory defaulting to the repo root, and `wrangler.toml` set `pages_build_output_dir = "."`. Every file in the repo was therefore served publicly. A second copy was being served on the LAN by a stray `python3 -m http.server 8085`.

**What was exposed**, verified live with matching content-types and content-lengths:

| Path | Contents |
|---|---|
| `/migrations/001_schema.sql` | Admin PIN hash (unsalted SHA-256) |
| `/wrangler.toml` | `SITE_SECRET` in plaintext |
| `/agent.md`, `/HANDOFF-2026-07-28.md` | The admin PIN in plaintext prose |
| `/functions/**` | Full server source |
| `/AUDIT.md`, `/UX-AUDIT.md`, `/context.md` | Internal audit trail |

**Response taken.**
- Stray LAN server killed.
- Old PIN `talhatheboss` and old `SITE_SECRET` revoked; both must be treated as permanently compromised — they remain in git history.
- PIN hashing moved from unsalted SHA-256 to PBKDF2-SHA256 with a per-install salt.
- Site moved to `public/`; `pages_build_output_dir` scoped to it. Verified: sensitive paths now 404 with no secret strings in any response body.
- `netlify.toml` added to make an accidental Netlify redeploy fail closed.

**Containment closed 2026-07-29.** The Netlify site was deleted by the owner. Verified: `/`, `/wrangler.toml`, `/migrations/001_schema.sql`, `/agent.md` and `/functions/**` all return 404 with Netlify's platform-level `Not Found` body — not a site-level 404 page — and no response body contains any secret marker. Re-run the check with the loop under Deploy Steps, pointed at the Netlify host.

Both exposed credentials were rotated regardless and remain compromised in git history; treat any reference to the old PIN or `SITE_SECRET` as historical. Search-engine caches may still hold snapshots of the exposed content for some time.

## Deploy Steps (Cloudflare)

**Prefix every wrangler call with `CLOUDFLARE_API_TOKEN=`.** A narrow token is exported in the
shell and shadows the working OAuth login; without the prefix these all fail with
*"Failed to automatically retrieve account IDs"*, which reads exactly like being logged out.

```bash
# ✅ DONE 2026-07-30 — D1 created, id already in wrangler.toml
#    npx wrangler d1 create dr-sumya-pervin-db

# ✅ DONE 2026-07-30 — schema applied to --remote and verified (4 tables + admin seed).
#    Note: remote D1 writes are blocked by the agent permission classifier; the
#    operator must run these directly.
#    npx wrangler d1 execute dr-sumya-pervin-db --remote --file=migrations/001_schema.sql

# ✅ DONE 2026-07-31 — both set on the production environment.
#    Note `pages secret`, not `secret`. Plain `wrangler secret put` is the Workers
#    command and silently does nothing for a Pages project. This was one of three
#    paths that caused G02.
#    npx wrangler pages secret put JWT_SECRET
#    npx wrangler pages secret put SITE_SECRET

# ⛔ BLOCKED — owner must first enable R2 in the Cloudflare dashboard. The API
#    refuses with code 10042; it is an account-level opt-in requiring accepted R2
#    terms and billing. The [[r2_buckets]] binding is resolved when the Functions
#    bundle is published, so a missing bucket fails the ENTIRE deploy, not just
#    gallery routes.
CLOUDFLARE_API_TOKEN= npx wrangler r2 bucket create dr-sumya-gallery

# ⬜ THEN deploy
CLOUDFLARE_API_TOKEN= npx wrangler pages deploy
```

Then in Cloudflare Dashboard → Pages → connect `drsumyapervin.com`, and add a WAF rate-limiting rule on `POST /api/auth/login` (there is no application-level login throttle).

After deploying, confirm the exposure stays closed:

```bash
for u in /migrations/001_schema.sql /wrangler.toml /agent.md /functions/lib/auth.js; do
  curl -s -o /dev/null -w "$u %{http_code}\n" "https://drsumyapervin.com$u"; done   # all 404
```

## Known Issues / Gotchas

- **`JWT_SECRET` must be set before deployment** — *set on production 2026-07-31.* Login returns 500 without it. There is deliberately no fallback (`functions/lib/auth.js:8`) — the previous fallback constant meant anyone reading the source could mint admin tokens.
- **`SITE_SECRET` must be set** — *set on production 2026-07-31.* Without it `GET /api/contact` returns 500 (`functions/api/contact.js:28`) rather than falling back to a default.
- **Both fail closed, and booking does not depend on either.** `onRequestPost` in `functions/api/appointments/index.js` has no `requireAuth`, so anonymous bookings work even with the secrets unset — a deploy missing them yields a site where booking succeeds while contact and CMS login break. Worth knowing before diagnosing a partial outage.
- **D1 migration must run before the site works** — *applied to remote and verified 2026-07-31.* There is no runtime seeder any more; one that invents a default PIN is a backdoor. Note remote D1 writes are blocked by the agent permission classifier, so the operator runs them directly.
- **A missing R2 bucket fails the entire deploy**, not just gallery routes — the `[[r2_buckets]]` binding is resolved when the Functions bundle is published. Do not assume R2 is a post-launch concern.
- **No signup flow** — one admin PIN, changeable via CMS Settings (requires current PIN, minimum 8 characters). If lost, reseed via a D1 query.
- **No login rate limit in code.** Add the Cloudflare WAF rule.
- **Booking flow:** bookings persist to D1, and the doctor must check the CMS — no push notification exists. If the API call fails the patient now sees an explicit failure, not a fabricated reference number.
- **Hero gradient contrast** is inherently fragile — any change to hero gradient colors needs contrast re-verification.
- **Anything added to the repo root is unpublished by default.** New patient-facing files go in `public/`.
- **Use `npm run dev`**, which wraps `wrangler pages dev public --local`. A plain static server cannot run Pages Functions, so `/api/*` 404s and the site breaks in ways that aren't real — and pointed at the repo root, that is what published the original leak.
- **`wrangler.toml` must keep a `compatibility_date`.** Unset, wrangler defaults it to *today*, which fails outright when the local wrangler is newer than the installed `workerd`, and silently shifts runtime behaviour as the date advances. Bump deliberately and re-test.
- **The booking form must keep its submit guard.** `public/index.html` carries `onsubmit="return false"` on `#bookingForm`, and the submit button ships `disabled`, enabled by `main.js` once the handler attaches. Without the form-level guard, a submit before hydration does a native GET to `/?` and the patient's booking is lost silently — Enter in a text field reaches this too, so a button-only guard is insufficient.
- **`npm run seed-pin`** regenerates the admin PIN seed. Run it in a real terminal, never through an agent session: it prints only salt and hash so the plaintext stays out of transcripts and logs, which is the failure that lost the previous PIN.
- **A real pointer click on the booking submit button is unverified.** Scroll-reveal elements were seen intercepting pointer events over it. See `AUDIT-ROUND-3.md` for the reasoning; resolve before launch.

`Account.Turnstile:Edit` token v3 records as being minted because the wrangler OAuth grant lacks

**Blast radius: Turnstile only. No D1, no R2, no Pages, no Workers, no DNS.** Patient data in D1

> #### ⚠️ Two wrong identifications were made before this one. Do not repeat them.
>
> 1. **"Narrow token, empty `/accounts` proves it."** Wrong. A Turnstile-only token simply does
>    not grant account listing. An empty `/accounts` says nothing about a token's power.
> 2. **"`cfut_` means it is an R2 API token, so assume All buckets / Admin R&W."** Wrong. That
>    came from one line in an R2 doc; `cfut_` is Cloudflare's modern prefix for API tokens
>    generally, and R2 tokens *are* user API tokens, so the prefix is not R2-specific. The
>    `All buckets / Admin Read & Write` scope belonged to two unrelated tokens on the R2 page,
>    neither of which is this one.
>
> **Also: R2's S3 `AccessDenied` is uninformative about permissions.** A controlled retest showed
> a real AccessKeyId with a *deliberately wrong* secret returns the identical `AccessDenied` as
> the derived secret, while a bogus AccessKeyId returns `Unauthorized`. It cannot distinguish
> "authenticated but unauthorised" from "bad signature".
>
> **The lesson: read the scope off the dashboard. Do not infer a credential's power from error
> codes or token prefixes.**

Also verified: the secret value appears **0 times** in the full git history (`git log --all -p`).
Only the token *id* is in committed docs, and an id is not a credential. The repo is **private**.

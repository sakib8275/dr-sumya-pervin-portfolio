### Two fixes found and made during T6 (uncommitted)

1. **`wrangler.toml` had no `compatibility_date`.** It defaulted to *today* and outran the
   installed `workerd` ("requires compatibility date X, newest supported is Y") — the dev
   server would not start. Now pinned to `2026-07-29`. Verified: starts clean with no flag.
2. **`public/index.html` booking form had no submit guard.** No `action`/`method`, so a submit
   before `main.js` attached did a native GET to `/?` — page reloaded, fields cleared, booking
   silently lost. On the stated audience (mid-range Android, slow connections, 1131-line
   `main.js`) that is reachable. Fixed with `onsubmit="return false"` on the form **plus** a

   would have missed it. Verified both directions: no navigation pre-hydration via click,

### ~~Open question~~ — **closed 2026-07-30 (later session). No overlay. Bookings are clickable.**
Real pointer clicks with default actionability waits — no `force`, no `requestSubmit()`, no
manual scrolling — succeed on the booking submit button at **three viewports** (508×894,
1280×800, 390×844 Android). Each produced `POST /api/appointments` → **201** with a distinct
server id, the confirmation panel echoed the submitted name, and all three rows were then read
back out of local D1 with ids matching the response bodies (`book-b9e9ac18`,
`book-11efa8e4`, `book-be25df0e`). The primary conversion path is not blocked.

**Why the previous session saw `[data-r]` "intercepting" — two independent effects, neither a bug:**

1. **`.modal-overlay` is `opacity: 0; pointer-events: none` until `.active`** (`style.css:1307`).
   The submit button still has a non-empty bounding box and no `visibility: hidden` while the
   modal is closed, so Playwright rates it **visible** and proceeds to hit-test — and the hit
   passes *through* the `pointer-events: none` overlay onto whatever page content is behind it,
   which is `[data-r]` sections. Reproduced exactly: with the modal closed, `elementFromPoint`
   at the button's centre returns `DIV.namecard.in`. **A `[data-r]` hit on that button is the
   signature of a closed modal, not of an overlay.**
2. **`.modal-box` is `max-height: 90vh; overflow-y: auto`** (`style.css:1327`), so the submit
   button sits below the box's *internal* scroll fold. With the modal open and fully settled,
   an un-scrolled `elementFromPoint` at the button's centre returns the overlay backdrop below
   the box. `page.click()` scrolls it into view first, so this never affects a real click —
   and a real user scrolls the modal the same way.

Both were verified against the settled state (`.active`, overlay `opacity: 1`, `.modal-box`
`transform: matrix(1,0,0,1,0,0)`, plus a 700 ms margin past the 0.3 s transitions), so this is
not "animations hadn't finished."

**Gotcha for whoever writes T7:** the natural selector `.open-booking` matches **7 elements**,
and the first in DOM order is the nav CTA, which is `display: none` below 820 px. `page.click('.open-booking')`
therefore fails with "element is not visible" at mobile widths — a harness error that reads
exactly like a broken CTA. Scope it: `.hero-cta a.open-booking`.

## Gotchas for the next agent

- **Never serve this with a plain static server.** `python3 -m http.server` / `npx serve`
  cannot run Pages Functions, so `/api/*` 404s and the site looks broken in ways that aren't
  real — and pointed at the repo root, that is what published the original leak.
  Use `npm run dev` (wraps `wrangler pages dev public --local`).
- **`npm run dev` used to exit 127 — fixed 2026-07-30.** The script called bare `wrangler`
  while `wrangler` was declared in neither `dependencies` nor `devDependencies`, so
  `node_modules/` held only `jose`, there was no `node_modules/.bin/`, and the documented dev
  command could not run at all. Now declared as `devDependencies.wrangler ^4.115.0` (35 packages,
  0 vulnerabilities), which also pins the version instead of letting `npx` float it. Verified
  after the fix: server ready on `:8788`, `/` serves the real page, and **`/api/appointments`
  returns 401, not 404** — the distinction that proves Pages Functions are running rather than
  the asset fallback answering.
- **Local D1 holds test data**, including a throwaway local-only PIN and several probe
  bookings, one carrying XSS payloads. It lives in `.wrangler/` (gitignored) and is *not*
  production. The throwaway value is deliberately not recorded here; reseed with
  `npm run seed-pin` and a local `UPDATE admin_settings`, or delete `.wrangler/` to reset.
- **Playwright `page.route()` persists across navigations.** A stale route abort made a
  known-good success path look broken this session, which nearly read as a regression. Call
  `page.unrouteAll()` between phases.
- **`requestSubmit()` ≠ a user click.** It bypasses hit-testing. Useful to isolate harness
  problems from code problems, but it is not evidence the button is clickable — see the open
  question above.
- **A status code is not a result.** A prior session concluded `.assetsignore` "did not work"
  from 200s that were the index.html fallback. Every check this session asserts on response
  *bodies* and rendered DOM. Keep that standard.
- **The old PIN and `SITE_SECRET` are in git history permanently** and stay compromised.
  Rotation, not scrubbing, was the response. Treat any reference to them as historical.
- **`AUDIT.md` / `FIXPLAN.md` are superseded** (pre-migration Express codebase).
  `UX-AUDIT.md` / `UX-FIXPLAN.md` are partly superseded.
- **Scope discipline:** per user memory, don't volunteer findings about sibling projects.
  `Desktop/portfolio-astro/` and `Desktop/Portfolio/` are different projects.
